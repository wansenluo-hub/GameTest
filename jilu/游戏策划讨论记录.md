# 徒步亚马逊：赛博徒步 - 游戏策划讨论记录

## 项目概述

**游戏名称**：徒步亚马逊：赛博徒步 (Walking the Amazon: Cyber Trek)

**游戏类型**：轻度生存模拟、决策驱动、点击式冒险

**核心概念**：基于埃德·斯塔福德真实徒步经历改编（改编以避免侵权），860天旅程 = 860分钟游戏时间（最简模式约60分钟）

**开发团队**：2人小团队

**技术选型**：Godot 4 + GDScript

---

## 一、核心设计要点

### 1.1 时间系统
- **游戏开始时间**：固定2030年
- **玩家选择**：出发月份和日期（如2030年6月15日）
- **时间压缩**：860天游戏内时间
- **每日时段**：6个时段/天，每时段4小时游戏内时间
- **真实日期计算**：游戏会显示真实日期（如2031年6月5日）+ 游戏天数（第355天）

### 1.2 难度设置
三个难度等级：

| 难度 | 初始资金 | 状态衰减 | 事件危险度 | 天数上限 | 预计时长 |
|------|----------|----------|------------|----------|----------|
| 简单 | $3000 | 0.7x | 低 | 无限制 | 40-50分钟 |
| 正常 | $2000 | 1.0x | 中等 | 无限制 | 60-80分钟 |
| 困难 | $1200 | 1.3x | 高 | 1200天 | 90-120分钟 |

### 1.3 角色创建
- **强制命名**：玩家必须输入名字（2-12字符，中英文数字）
- **出发日期**：选择月份和日期
- **季节提示**：根据出发时间自动显示难度提示

### 1.4 状态系统（7个核心状态）
1. **体力** (Stamina) - 行军消耗，休息恢复
2. **精力** (Energy) - 心理状态，影响决策
3. **饱食** (Food) - 饥饿度，每时段消耗
4. **水分** (Water) - 口渴度，炎热加速消耗
5. **健康** (Health) - 疾病/受伤，低于0死亡
6. **体温** (Temperature) - 环境影响，过高中暑/过低失温

### 1.5 季节与天气系统

#### 四季定义（南美热带气候）
- **春季** (3-5月)：雨季末期，洪水风险高，难度★★★☆☆
- **夏季** (6-8月)：旱季初期，天气稳定，难度★★☆☆☆（推荐）
- **秋季** (9-11月)：旱季末期，极度干燥，难度★★★★☆
- **冬季** (12-2月)：雨季中期，暴雨频繁，难度★★★★★

#### 天气类型
- ☀️ 晴天：标准状态
- 🌧️ 小雨：体力消耗+20%，体温-5
- ⛈️ 暴雨：体力消耗+50%，体温-10，洪水风险
- 🌫️ 雾：能见度低，迷路风险

#### 地形 × 季节 动态难度
每种地形在不同季节有不同的难度系数：
- **安第斯山区 + 冬季**：大雪封山，体力消耗+60%
- **热带雨林 + 夏季**：干燥舒适，最佳时机
- **热带雨林 + 冬季**：暴雨洪水，体力消耗+50%
- **沼泽区 + 冬季**：完全淹没，体力消耗+60%

### 1.6 四个路段
1. **安第斯山区** (1-120天)：高海拔、寒冷、卢克同行
2. **红色区域** (121-360天)：毒贩威胁、Cho招募、疾病高发
3. **过渡地带** (361-600天)：沼泽、洪水、GPS损坏
4. **巴西冲刺** (601-860天)：意志考验、装备老化、终点在望

## 二、游戏玩法机制

### 2.1 六大行动
1. **🚶 行军**：推进进度，消耗体力，触发事件
2. **😴 休息**：恢复体力/精力，消耗时间
3. **🏹 狩猎**：获得食物，消耗体力（困难模式重要赚钱途径）
4. **🏕️ 搭建**：建营地，提升休息效果
5. **💊 治疗**：使用医疗物品
6. **🔧 修理**：维修装备耐久度

### 2.2 经济系统
- **初始资金**：根据难度不同
- **购买物品**：村庄补给（食物、药品、装备）
- **雇佣向导**：卢克、Cho（可砍价）
- **赚钱途径**（困难模式）：
  - 狩猎卖肉
  - 采集森林资源
  - 村庄临时打工

### 2.3 事件系统

#### 事件数量规划（总计约194个）
- **重大事件**（需要选择）：90个
  - 生存危机：30个
  - 社交选择：20个
  - 自然灾害：15个
  - 野生动物：15个
  - 装备问题：10个
  
- **小事件**（文本提示）：85个
  - 风景描述：30个
  - 心理独白：20个
  - 小发现：20个
  - 向导对话：15个

- **自动事件**：19个
  - 里程碑：10个
  - 季节切换：4个
  - 向导剧情：5个

#### 事件触发机制
- 25%触发重大事件
- 40%触发小事件
- 35%无事件纯推进

### 2.4 向导系统
- **卢克**：路段一陪伴（安第斯山区），提供基础补给
- **Cho**：路段二招募（红色区域），更强的协助能力
- **雇佣机制**：可砍价，向导提供自动补给和安全加成

## 三、创新功能：半联机遗言系统

### 3.1 核心玩法
- **玩家死亡时**：可以留下遗言（可选，最多100字）
- **其他玩家**：游戏中随机遭遇前人遗骸，看到遗言
- **互动**：可以点赞👍或祈祷🕯️

### 3.2 遗言显示格式
```
麦克（蟒蛇袭击）2031年6月5日：
"红色区域的河边千万小心，蟒蛇会藏在树根下面。
我以为它只是一截木头，结果被咬了。
如果被咬，立刻用抗蛇毒血清，不要犹豫。"

👍 124人点赞 | 🕯️ 67人祈祷
```

### 3.3 死因类型
- 疟疾、蟒蛇袭击、饥饿、脱水、失温、中暑
- 溺水、美洲豹袭击、伤口感染、体力耗尽
- 遭遇毒贩、山体滑坡、中毒、迷路、健康耗尽

### 3.4 触发机制
- **随机遭遇**：每行军10次，30%概率触发
- **死亡高发区**：特定天数段自动提示
- **遗言墙**：主菜单查看全球统计数据

### 3.5 技术实现
- **推荐方案**：简单后端API（Node.js/Python Flask）+ PostgreSQL
- **服务器成本**：约$10/月
- **内容审核**：自动敏感词过滤 + 举报机制
- **隐私保护**：玩家使用自定义名字（非Steam用户名）

### 3.6 开发阶段建议
- **MVP版本**（12小时）：基础遗言提交和显示
- **完整版本**（20-25小时）：含遗言墙、统计数据
- **建议**：先做MVP，EA期间根据反馈决定是否上云

## 八、关键设计决策记录

### 8.1 事件数量
- **决定**：约194个事件（不止42个）
- **原因**：按10秒浏览一个事件计算，需要足够内容撑起游戏时长
- **实现**：重大事件90个 + 小事件85个 + 自动事件19个

### 8.2 剧本内容
- **决定**：埃德事件作为参考，需要改编
- **原因**：避免侵权问题
- **责任人**：策划（用户）负责剧本和对话填充

### 8.3 困难模式平衡
- **问题**：资金少导致推进慢，时长无限增长
- **解决方案**：
  1. 天数硬上限（1200天）
  2. 渐进式奖励（完成路段给钱）
  3. 困难模式专属赚钱途径（狩猎卖肉、采集、打工）
  4. 困难模式"善意"事件（村民赠送物资）
  5. 关键物资保底机制

### 8.4 季节系统
- **决定**：玩家可选择出发时间，不同季节不同难度
- **影响**：季节 × 地形 = 动态难度系数
- **细节**：夏季出发最简单，冬季出发最困难

### 8.5 体温系统
- **决定**：新增第7个状态条
- **原因**：季节和天气对真实徒步影响巨大
- **机制**：环境温度、运动、天气、装备综合影响体温

### 8.6 遗言系统命名
- **决定**：玩家必须自己起名，不给默认名
- **格式**：名字（死因）日期：遗言
- **示例**：麦克（蟒蛇袭击）2031年6月5日：遗言内容
- **原因**：增加代入感和真实感

### 8.7 时间显示
- **决定**：固定2030年开局，玩家选月份和日期
- **显示**：真实日期（2031年6月5日）+ 游戏天数（第355天）
- **计算**：自动处理跨月、跨年、闰年
